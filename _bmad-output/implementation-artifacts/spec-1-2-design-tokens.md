## Intent

**Problem:** `DESIGN.md`'s YAML frontmatter is the design source and there is no code source. Without one, every later story hard-codes raw hex, px and durations, and the design document drifts from the shipped app with no gate able to tell which side went wrong (AD-17 names three such defects already found in the reference prototype). Story 1.3 and 1.4 build components on these tokens; if the token shape is wrong now, they compose on sand.

**Approach:** Hand-write `src/ui/theme/tokens.ts` as the typed, dependency-free code source for all five token families plus the component tokens and the `ntInk` filter, and add a CI test that parses `DESIGN.md`'s frontmatter and asserts the two agree on every name and value — including the set's completeness (no second palette) and the measured `ash` contrast. Add the AD-17 ESLint rule that forbids raw values under `src/ui/**` outside `src/ui/theme/**`.

## Boundaries & Constraints

**Always:** `DESIGN.md` frontmatter is authoritative for values; where it and the AC disagree on a *value*, `DESIGN.md` wins (AD-20). `tokens.ts` is dependency-free — no `yaml` import at runtime, so the shipped bundle carries no parser; only the sync test imports the parser. Components read tokens and never hard-code a raw value (AD-17). Every token is `readonly`; absence is `null`, never `undefined`. Values are read from the files, never retyped from memory.

**Never:** Do not write a second palette, a light theme, or a theme-switching surface — the app is dark-only and a second palette must fail the test. Do not restate the 14 hex values or the 9 type values in this spec: `DESIGN.md` is the single source and retyping invites drift. Do not build the token-consuming components (`Rule`, `Seal`, `Chip`, …) — Story 1.3 owns document components, Story 1.4 interaction components; 1.2 ships tokens and their gate only. Do not add placeholder gates for stories that do not exist yet. Do not modify `DESIGN.md`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| HAPPY_PATH | `DESIGN.md` frontmatter and `tokens.ts` agree on every family | sync test passes; token counts equal the declared counts | No error expected |
| VALUE_DRIFT | one token value changed in either source only | CI fails, naming the token path, the design value and the code value (AD-17) | `test.fail` with all three facts in the message |
| SECOND_PALETTE | a light palette added to either source | completeness assertion fails even though every shared name still agrees | `test.fail` naming the extra palette key |
| MISSING_YAML | `DESIGN.md` absent or its frontmatter unparseable | the test fails loudly with a parse/read error | `test.fail` — never a silent pass on an empty set |
| RAW_VALUE | a hex, px dimension or literal duration under `src/ui/**` outside `src/ui/theme/**` | `no-restricted-syntax` error naming AD-17 | lint error; the theme directory is unaffected |
