## Intent

**Problem:** The repository holds planning artifacts and no code. Every later story imports the four-layer import boundary, the TypeScript strictness set, the two-project Jest setup, the CI pipeline, and the `Result`/`Logger`/`IdFactory` primitives. Built late, they are retrofitted across five finished epics; built absent, later epics author strings, SQL and engine code that no gate has ever checked.

**Approach:** Hand-author a from-scratch Expo SDK 57 project — no starter template, because the architecture specifies none. Write the boundary and quality configuration before any application code, commit one CI pipeline as the sole place gates are declared blocking, and prove the boundaries by making the violating cases fail rather than by asserting they would.

## Boundaries & Constraints

**Always:** `app.config.ts` is the only source of native config truth; `ios/` and `android/` are CNG-generated and gitignored. The bundle identifier and package name base is `com.nighttrace.app`, suffixed `.dev` and `.preview` for the non-production variants. `expo-dev-client` with dev/preview/production profiles; no EAS anywhere in the path and Expo Go is not a delivery target. `fastlane/` sits at the repo root, never inside a generated native directory. Every id is branded and every field `readonly`; absence is `null`, never `undefined`; no `any`; no `as` outside `src/db/mappers/**` and validator output. `IdFactory` is the only id producer, `Logger` the only module that logs.

**Never:** No adding, copying or vendoring a template. No `console.*` in `src/` outside `src/services/Logger.ts`. No SQL string literal outside `src/db/repositories/**`. No import of `react`, `react-native`, `expo*` or `zustand` under `src/engine/**`, and no `Date.now()`, `Math.random()` or `performance.now()` there. No signing material committed. No gate declared CI-blocking before `.github/workflows/ci.yml` runs it.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| KV round-trip | `kv.set('noticeAcknowledged', true)` then `kv.get` | `true` returned, typed at compile time | No error expected |
| KV absent key | `kv.get` for a key never written | `null` — never `undefined` | No throw |
| KV malformed value | stored JSON does not match the key's declared type | `null`, and a `Logger` line carrying no value | Parse failure returns `null`, never a boundary throw |
| Recoverable failure | a service hits an expected bad state | `ok: false` with a typed error | Returns `Result`, never throws |
| Programmer error | `invariant()` on a false condition | throws | Throw is the intended outcome |

## Design Notes

The gate list in NFR-17 spans stories 1.2, 1.5, 3.1 and 2.2, which do not exist yet. The epics AC resolves this itself: *a gate may not be described as CI-blocking until this pipeline runs it.* So 1.1 commits the pipeline and the gates with subjects, and each later story appends its gate to the same file. Do not create placeholder gates that assert nothing — an unimplemented gate that passes is worse than an absent one, because it reads as coverage.
